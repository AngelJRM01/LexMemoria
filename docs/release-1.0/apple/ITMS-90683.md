# Corrección del procesamiento Apple — build 19

El titular aportó un correo de Apple para LexMemoria (App Apple ID 6833461057), versión 1.0.0 build 18: rechazo ITMS-90683 por ausencia de NSPhotoLibraryUsageDescription y NSCameraUsageDescription; aviso adicional NSLocationWhenInUseUsageDescription. La transferencia de altool terminó correctamente, pero Apple no aceptó el procesamiento. No confundir ambos estados.

Revisión del código: los tres usos actuales de FilePicker son FileType.custom con extensiones explícitas: imagen de avatar, importación CSV y copia de datos. No hay captura de cámara, selección multimedia con FileType.image/media/audio ni una función de ubicación. file_picker 10.3.10 incluye por defecto la dependencia DKImagePickerController/PhotoGallery mediante su podspec. Su integración Swift Package Manager también añade la dependencia multimedia sin las opciones de exclusión del podspec.

Se configura CocoaPods y sus constantes Pod::PICKER_MEDIA=false, Pod::PICKER_AUDIO=false, Pod::PICKER_DOCUMENT=true, conservando el selector de documentos. Los workflows Apple de compilación desactivan Swift Package Manager para que se respeten dichas opciones. No se añaden descripciones ficticias de cámara o ubicación. La firma comprueba la ausencia de DKImagePickerController, DKPhotoGallery y DKCamera tanto en Podfile.lock como en frameworks empaquetados antes de subir.

La candidata pasa a 1.0.0+19. El workflow de firma reutiliza el certificado/perfil existente y, después de conservar la IPA, la transfiere directamente a App Store Connect con la clave temporal ya configurada. Limpieza de la clave siempre. No se envía a revisión ni se publica. El antiguo workflow separado corresponde históricamente al build 18 y no debe relanzarse para esta corrección.

Pruebas locales: 19 específicas superadas, sintaxis Bash/YAML comprobada. Las comprobaciones locales no acreditan compilación iOS, importación física de archivos ni aceptación Apple. Pendiente: ejecución macOS, procesamiento de Apple del build 19 y prueba física de avatar/CSV/copia. Si Apple sigue detectando referencias, revisar la dependencia concreta del binario resultante; no declarar permisos que la aplicación no utiliza por rellenar el formulario.
